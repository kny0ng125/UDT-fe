# 변경사항 템플릿 (테스트 커버리지 입력)

PR 설명이나 Notion 변경내역을 이 양식으로 적으면 `/test-coverage` 가 읽고
**테스트 필요 여부 / 단위·통합 / 넣을 케이스** 를 판단한다. 변경 1건 = 블록 1개. 모르면 `미정`.

> 이 양식은 사람이 작성하는 **참조 문서**다. 판단·작성은 `/test-coverage` 커맨드(Claude 조작 rule)가 한다.

---

## 🔖 [변경 제목 — 한 줄 요약]

- **변경 유형**: `기능 추가` | `기능 수정` | `기능 제거` | `리팩터(동작 불변)` | `버그 수정`
- **변경 대상(파일/심볼)**: 예) `useDeleteCurated` 훅 / `useRecommendStore.shouldLoadMoreContent` / `src/middleware.ts`
- **변경 성격**(해당 모두 체크 — 단위/통합/불필요를 가르는 핵심 신호):
  - [ ] 순수 로직·계산 (입력→출력, 부수효과 없음) → 단위
  - [ ] store 상태 변화 (zustand) → 단위(순수) 또는 통합(부수효과)
  - [ ] 네트워크 연동 (API·react-query 훅) → 통합/data
  - [ ] 훅 부수효과·사용자 상호작용 → 통합/interaction
  - [ ] UI 렌더/문구/스타일만 → 보통 불필요
  - [ ] 라우팅/미들웨어 동작 → 단위(로직)만, 실행 검증은 한계
- **무엇이 달라지나**: 입력 → 기대 출력 / 단계별 동작 (assert 로 바뀔 문장)
- **경계·예외 케이스**: 빈 배열, 0/최댓값, 401/500 응답, 중복 호출 등 반드시 검증할 것
- **기존 테스트**: `있음(파일/ID)` | `없음` | `모름`
- **작성자 판단**: `테스트 불필요` | `단위 필요` | `통합 필요` | `모름`
- **비고**: 백엔드 의존·제약·스펙 링크 등

## 작성 예시

### 🔖 A. 큐레이트 콘텐츠 일괄 삭제 훅 추가 (useDeleteCurated)
- **변경 유형**: `기능 추가`
- **변경 대상**: `useDeleteCurated` 훅 (`@hooks/profile/useDeleteCurated`)
- **변경 성격**: ☑ 네트워크 연동(API)
- **무엇이 달라지나**: `mutate(contentIds)` → `DELETE /.../bulk` body 에 `{contentIds}` 전달, 성공 시 `curatedContents` invalidate
- **경계·예외 케이스**: 단일 `[1]`, 다중 `[1,2,3]`, 서버 오류(500)
- **기존 테스트**: 없음 → **작성자 판단**: `통합 필요`
- → 판단: ✅ **통합/data** 생성 (MSW DELETE mock + invalidate spy)

### 🔖 B. 닉네임 입력란 테두리 색상 변경
- **변경 유형**: `기능 수정` / **변경 성격**: ☑ UI 스타일만
- **무엇이 달라지나**: 포커스 시 테두리 색만 변경, 로직 불변
- **작성자 판단**: `테스트 불필요`
- → 판단: ❌ 생성 안 함 (스타일은 jest 대상 아님)

### 🔖 C. 추천 페이지네이션 트리거 조건 9→14
- **변경 유형**: `기능 수정` / **변경 성격**: ☑ 순수 로직 ☑ store 상태
- **변경 대상**: `useRecommendStore.shouldLoadMoreContent`
- **무엇이 달라지나**: `currentIndex` 끝자리 4에서 트리거(기존 9)
- **경계·예외 케이스**: 14/24 트리거, 0·끝값 비트리거
- **기존 테스트**: `있음 — tests/unit/store/useRecommendStore.test.ts (L1~L4)`
- → 판단: ♻️ **기존 단위 테스트 갱신** (케이스 값 수정·추가)
